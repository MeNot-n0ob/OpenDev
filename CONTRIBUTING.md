# Contributing

Thank you for contributing! This project is a variant of [OpenCode](https://github.com/anomalyco/opencode). 

Contributions are reviewed based on their size and impact. 

## Change Types

| Change Type | Vote Required? | Who Votes? | Approval Threshold |
| :--- | :--- | :--- | :--- |
| **Small Changes** | No | — | — |
| **New Features** | Yes | Everyone | >= 2/3 |
| **Major Changes** | Yes | Eligible Project Voters | >= 3/4 |

---

## All votes are held using google forms

---
## 1. Small Changes
> **No vote required.** Merged by maintainers when ready.

* **Examples:** Bug/error/security fixes, minor optimizations, docs/typo corrections, and small non-breaking refactors.

---

## 2. New Features
> **Public vote required.** Open to everyone. Passes with **>= 2/3** approval (calculated as `Approve / (Approve + Reject)`).

* **Workflow:**
  1. Open a GitHub Issue/Discussion detailing the proposal.
  2. Maintainers classify the change and open a public Google Form vote.
  3. If passed, implement the feature and open a pull request referencing the vote.

---

## 3. Major Changes
> **Project-voter vote required.** Restricted to eligible project voters. Passes with **>= 3/4** approval.

* **Examples:** Architectural overhauls, replacing major components, and breaking changes.
* **Workflow:** Same as new features, but restricted to project voters and requires a **>= 3/4** threshold.

---

## 4. Voting & Integrity
* **Platform:** Conducted via a designated Google Form linked in the README/Discussions.
* **Options:** Approve, Reject, or Abstain. Ties fail.
* **Integrity:** Maintainers use Google Form controls to prevent duplicates and can invalidate fraudulent, automated, or spam votes.

---

## 5. Pull Requests & Code Guidelines
* **PR Best Practices:** Explain changes clearly, keep PRs focused, include tests, and reference any voting results. Do not combine unrelated changes.
* **Code Quality:** Follow project conventions, avoid unnecessary dependencies/duplication, and update documentation for user-facing changes.

---

## 6. Licensing & Upstream Code
* Derived from [OpenCode](https://github.com/anomalyco/opencode). 
* Contributors must preserve third-party copyright/licenses and ensure they have the legal right to distribute submitted code.

---

## 7. Maintainer Authority & Emergencies
* **Authority:** Maintainers review PRs, classify changes, resolve disputes, and manage votes.
* **Emergency Changes:** Maintainers can bypass voting *only* for critical security fixes, severe bugs, or data loss, and must document the bypass afterward.

---

## 8. Community Guidelines & Policy Changes
* **Guidelines:** Be respectful, constructive, and keep discussions relevant.
* **Policy Updates:** Changes to this file require approval from at least **three-quarters (3/4)** of eligible project voters.
