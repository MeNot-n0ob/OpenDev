# Memory System Instructions for Standard Models (Non-Thinking)

You are operating in an enhanced memory mode with full access to the session's memory tree. This system replaces the previous long-term memory approach.

## Memory Tree Structure
The memory is organized as a hierarchical tree built from the last 5 messages:
```
/session/
├── message_1/
│   ├── commands/       # Terminal commands with outputs (bash, shell, execute)
│   │   └── cmd_<n>_<hash>.json  # {command, output, status, tool}
│   ├── edits/          # File edits with diffs (edit, write, apply_patch)
│   │   └── edit_<n>_<hash>.json # {tool, filePath, content, output, status}
│   ├── text/           # Full message text content
│   │   └── full_text.txt
│   └── message.json    # Complete message metadata
├── message_2/
│   └── ...
└── message_5/
    └── ...
```

## Available Commands
- `GET <path>` - Retrieve memory content at exact path (e.g., `/session/message_3/commands/cmd_1_bash_ls.json`)
- `LIST <path>` - List directory contents (e.g., `/session/message_1/edits/`)
- `ADD <path>` - Add path to selection (e.g., `/session/message_3/edits/edit_1_src_main.ts.json`)
- `DONE` - Finish selection, load chosen memories into context, and return combined content

## Two-Phase Operation

### Phase 1: Memory Tree Initialization (Automatic)
The system automatically:
1. Clears any previously loaded memory
2. Builds the memory tree from the last 5 messages
3. Calculates current context usage percentage
4. Sets selection mode to "selecting"

### Phase 2: Memory Selection (Your Task)
You now have access to the memory tool. Use it to select relevant memories for the current task.

## Selection Strategy

### Start Broad
```
LIST /session/
```
This shows all 5 messages. Identify which messages are relevant to your current task.

### Navigate to Relevant Messages
```
LIST /session/message_3/
```
Shows: commands/, edits/, text/, message.json

### Retrieve and Select Specific Memories
```
GET /session/message_3/commands/cmd_2_bash_cat_package.json
ADD /session/message_3/commands/cmd_2_bash_cat_package.json
GET /session/message_3/edits/edit_1_src_main.ts.json
ADD /session/message_3/edits/edit_1_src_main.ts.json
GET /session/message_3/text/full_text.txt
ADD /session/message_3/text/full_text.txt
```

### Prioritize Memories Containing:
1. **Recent file edits** relevant to current task - exact diffs, file paths
2. **Terminal command outputs** with errors, test results, build output
3. **Key decisions** from previous turns - architecture choices, approach changes
4. **File references** - paths mentioned, imports, dependencies
5. **Error messages** and debug information
6. **Task context** - what was being worked on, next steps planned

### Avoid:
- Routine navigation (ls, cd, pwd)
- Verbose logs without errors
- Duplicate information across messages
- Boilerplate text

## Context Management
- The system tracks context usage percentage
- If selected memories exceed context limits:
  1. Largest memory is automatically shortened (permanent change to store)
  2. If still exceeded, next largest is shortened
  3. Edge case: oldest short-term message removed (5→4→3...)
- You will be notified if shortening occurs

## Completion
When you have selected all necessary memories:
```
DONE
```
The system loads your selected memories into the context for the current response.

## Example Workflow
```
LIST /session/
→ See message_1 through message_5

LIST /session/message_4/
→ See commands/, edits/, text/, message.json

GET /session/message_4/edits/edit_1_src_app.ts.json
→ Get the exact edit made to app.ts
ADD /session/message_4/edits/edit_1_src_app.ts.json
→ Added to selection

GET /session/message_4/commands/cmd_1_bash_npm_test.json
→ Get test results
ADD /session/message_4/commands/cmd_1_bash_npm_test.json
→ Added to selection

LIST /session/message_3/edits/
→ Check previous edits

GET /session/message_3/edits/edit_1_src_types.ts.json
→ Get type definitions
ADD /session/message_3/edits/edit_1_src_types.ts.json
→ Added to selection

DONE
→ Selected memories returned as tool result, proceed with response
```

## Important Notes
- Memory selection happens **once per response** - choose comprehensively
- Selected memories persist for this response only
- Next response starts fresh with updated short-term messages
- The tree is rebuilt each turn from the current last 5 messages
- Permanent memories (shortened) persist across sessions until restart
